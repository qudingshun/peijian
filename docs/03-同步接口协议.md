# 03 · 同步接口协议

- 基地址：`http://<电脑IP>:8000`
- 鉴权：请求头 `X-Sync-Token: <令牌>`（也支持 `?token=` 查询参数，方便浏览器直接点链接下载）
- 数据格式：JSON（UTF-8）；导出为 xlsx
- 时间：毫秒时间戳（除 `serverTime` 等展示字段）

## 1. 配对

电脑端首页展示二维码，内容格式：

```
PEIJIANSYNC1|ip=192.168.1.5|port=8000|token=AbCdEf123|ver=1
```

PDA 扫码后写入地址与令牌。也支持手输 `192.168.1.5:8000#AbCdEf123`。

令牌保存在电脑端 `data/token.txt`；删除该文件重启服务即重新生成。

## 2. GET /api/v1/health

无需令牌，用于「测试连接」。

```json
{ "ok": true, "app": "peijian-sync", "version": "0.1.0",
  "time": "2026-11-16 12:41:57", "source": "E:\\peijian\\配件记录.xlsx" }
```

## 3. GET /api/v1/packing?since=rev[&limit=n&after_key=key]

增量拉取打包数据。`since=0` 表示全量。支持两种模式：

- **不传 `limit`（或 `limit=0`）**：一次性返回 `rev > since` 的全部箱（老客户端兼容路径）。
- **传 `limit=n`**：分页返回，配合 `after_key` 游标逐页拉取，避免 2 万箱一次性读入内存。`n` 上限 2000（超出按 2000 处理）。

分页请求示例：

```
GET /api/v1/packing?since=0&limit=1000
GET /api/v1/packing?since=0&limit=1000&after_key=P108580%7C1   # 用上一页 next_since/next_after_key 继续
```

响应新增分页字段（`has_more=false` 时终止）：

```json
{
  "ok": true,
  "rev": 12,
  "count": 2,
  "has_more": true,
  "next_since": 12,
  "next_after_key": "P108580|1",
  "serverTime": "2026-11-16 12:41:57",
  "boxes": [
    {
      "customerCode": "W00305",
      "customerName": "WHIRLPOOLJAPANCO.,LTD.",
      "salesperson": "王世会",
      "country": "日本",
      "orderNo": "P108580",
      "boxNo": "1",
      "packDate": 1719936000000,
      "dimension": "56*33*10",
      "volume": 0.018,
      "grossWeight": 4.2,
      "packingUnit": "波轮工厂",
      "remark": "",
      "items": [
        {
          "partCode": "301B120030246",
          "englishName": "OperatingManualforTV80L/90L",
          "partName": "操作说明书TV80L/90L",
          "quantity": 30,
          "machineModel": "*YWM-TV80L(日本)",
          "remark": ""
        }
      ],
      "rev": 12,
      "status": "IN_STOCK",
      "barcode": "W00305-P108580-1",
      "sourceRow": 2
    }
  ]
}
```

约定：

- `rev` 是**本次返回后的服务端版本号**（每页都相同），PDA 在**所有分页落库成功后**才把它记为本地 `lastRev`；中途失败下次从原 `since` 重拉，落库幂等；
- 只返回 `rev > since` 的箱。**首屏**（不带 `after_key`）严格按 `rev > since` 取数——`since` 表示「已完整同步到的版本」，该版本整批不重发；**续页**（带 `after_key`）在相同 `rev` 内按 `(rev, source_key) > (next_since, after_key)` 继续，因为一批箱共享同一个 `rev`；
- `has_more=true` 时用本页 `next_since` / `next_after_key` 请求下一页，`false` 表示结束；本页为空但 `has_more=true` 视为异常；
- 同一箱 `rev` 更旧时 PDA 默认不覆盖；
- 每个箱附带 `status`（`IN_STOCK` / `SHIPPED` / `VOID`），**由服务端权威维护**：PDA 换机拉全量时据此还原已发出箱，避免重复出库；若本机仍有未上传的出库事件（发货单 `syncedAt IS NULL`），则以本地状态为准；
- 请求会触发服务端检查 Excel 是否变化，变了先自动导入。

## 4. POST /api/v1/shipments

上传一张已完成的发货单。

```json
{
  "device": "PDA-CRUISE2",
  "uid": "d3f1c0...（32 位，PDA 生成，幂等键）",
  "docNo": "FH20261116103000",
  "customerCode": "W00305",
  "customerName": "…",
  "receiver": "张三 / 顺丰 SF123",
  "operator": "李四",
  "note": "",
  "createdAt": 1794804000000,
  "finishedAt": 1794804300000,
  "boxes": [
    {
      "barcode": "W00305-P108580-1",
      "orderNo": "P108580",
      "boxNo": "1",
      "customerCode": "W00305",
      "customerName": "…",
      "scannedAt": 1794804100000,
      "items": [ { "partCode": "301B120030246", "partName": "操作说明书", "quantity": 30 } ]
    }
  ]
}
```

响应：

```json
{ "ok": true, "duplicate": false, "conflicts": [], "receivedAt": 1794804135402 }
```

- 同一 `uid` 重复上传返回 `duplicate: true`（幂等，不重复入库、不重复标箱）；
- 服务端用 `barcode_norm` 索引定位箱，按 `status='IN_STOCK'` 条件更新为 `SHIPPED`；此后导出的库存清单自动扣减；
- **整单原子性**：任一条箱码已被发出或系统里不存在时返回 `409`，`conflicts` 列出冲突箱码，整单不入库、不改状态。PDA 应在核实后撤回本机箱并重扫，不要直接重试上传。

```json
{
  "detail": {
    "ok": false,
    "error": "部分箱已被其他设备发出或不存在，本单未入库",
    "conflicts": ["W00305-P108580-1"]
  }
}
```


## 6. POST /api/v1/reconcile

对账：PDA 上报本机全部箱的摘要，服务端返回两端差异并下发权威箱数据。这是**只读接口**（不修改服务端状态），用于换机、多 PDA、离线太久后主动发现分歧，避免靠逐条规则补救。

请求体：

```json
{
  "boxes": [
    { "boxNorm": "W00305P1085801", "rev": 12, "status": "IN_STOCK" }
  ]
}
```

- `boxNorm`：归一化箱码（去分隔符、大写），与本地 `barcodeNorm` 一致；
- `rev`：本机记录的该箱版本号；`status`：本机当前状态；
- 上报全量（2 万箱只传三列摘要，约几百 KB），不要只传增量。

响应：

```json
{
  "ok": true,
  "serverRev": 13,
  "serverCount": 20929,
  "clientCount": 20928,
  "diff": {
    "missing": ["W00305P1085802"],
    "extra": [],
    "stale": ["W00305P1085801"]
  },
  "boxes": [
    { "customerCode": "W00305", "orderNo": "P108580", "boxNo": "1",
      "barcode": "W00305-P108580-1", "rev": 13, "status": "SHIPPED",
      "items": [ { "partCode": "301B120030246", "partName": "操作说明书", "quantity": 30 } ] }
  ]
}
```

差异语义：

| 字段 | 含义 | PDA 处理 |
| --- | --- | --- |
| `missing` | 服务端有、本机无（含首次拉不到的删行箱） | 用 `boxes` 里的完整数据补入 |
| `stale` | 两端都有但 `rev` 或 `status` 不一致 | 用 `boxes` 里的完整数据按服务端版本刷新 |
| `extra` | 本机有、服务端从未有过（本地脏数据） | 置 `VOID` 软删除；有未同步出库事件的箱跳过，避免丢单据 |

- `boxes` 只含 `missing + stale` 的完整箱数据（含 `items`、`status`），PDA 据此精确补差，无需全量重拉；
- `extra` 仅报告，服务端不自动删除任何箱；
- 对账完成后把本地 `lastRev` 推进到 `serverRev`。

**源表删行（墓碑）的同步路径**：服务端 `import_xlsx` 检测到 Excel 删行后，把对应箱标为 `status=VOID` 并递增 `rev`（保留记录，不物理删除），因此它会出现在对账的 `missing`/`stale` 里，随完整数据下发；PDA 按服务端 `VOID` 落地，库存自动扣减。`SHIPPED` 箱不因源表删行改写（保留出库历史）。源表重新加回该箱时，`VOID` 会复活为 `IN_STOCK`。首次导入不做墓碑，避免误删。

## 8. 导出接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/export/inventory.xlsx?scope=stock` | 库存清单（仅 `IN_STOCK`）+ 物料汇总 |
| `GET /api/v1/export/inventory.xlsx?scope=all` | 全部打包记录 + 物料汇总 |
| `GET /api/v1/export/shipments.xlsx` | 出库明细 + 发货单汇总 |

库存清单 17 列与 `配件记录.xlsx / 打包记录` 顺序一致。
物料汇总列：配件编码 / 配件名称 / 英文描述 / 整机型号 / 数量合计 / 箱数 / 明细行数，末行合计。

## 10. GET /api/v1/reload

强制重新解析 Excel（等价于首页「强制重新导入」）。一般不需要：每次业务请求都会自动检测文件变化。

## 11. 错误约定

| HTTP | 含义 | PDA 提示 |
| --- | --- | --- |
| 401 | 令牌不匹配 | 「配对令牌不对，请在电脑端重新生成配对码」 |
| 400 | 缺少 `uid` 等必填字段 | 直接显示服务端 `detail` |
| 409 | 箱已被其他设备发出 / 不存在 | 列出 `conflicts` 箱码，提示核实后撤回重扫 |
| 500 | 找不到 Excel / 解析失败 | 按提示检查 `配件记录.xlsx` 路径 |

业务错误统一返回 `{"ok": false, "error": "…"}`；HTTP 状态可能仍是 200，PDA 同时判断 `ok` 字段。
