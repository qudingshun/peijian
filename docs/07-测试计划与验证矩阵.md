### 3.2 改造方案（本轮**不落地**，仅方案）

**目标**：令牌不再出现在 URL 与明文 HTTP 中，同时保留浏览器可用的下载/标签入口。

| 步骤 | 内容 | 涉及文件 |
| --- | --- | --- |
| S1 服务端只认 Header | `check_token()` 删除 query 分支；浏览器专用路由改用**短期会话 Cookie**（`POST /session` 用令牌换 HttpOnly Cookie，2h 过期）或仅限 `127.0.0.1` 回环直连 | `pc-server/server.py` |
| S2 浏览器链接去令牌 | 首页 5 个下载/标签/重载链接与 `label_img_src()` 去掉 `?token=`，改走 Cookie 会话 | `server.py` 996-998、1156-1167 |
| S3 启用 HTTPS | 生成自签证书（内网无域名），`uvicorn --ssl-keyfile/--ssl-certfile`；或前置 Nginx 终止 TLS | `启动同步服务.bat`、`pc-server/` |
| S4 PDA 信任自签 CA | `network_security_config.xml` 增加 `<certificates src="@raw/pinned_ca"/>`；`cleartextTrafficPermitted` 改 `false`；`serverUrl` 改 `https://` | `res/xml/network_security_config.xml`、`res/raw/pinned_ca.pem`、`Prefs` |
| S5 配对与文档 | 配对文本端口/协议改 https；docs/03、docs/04 同步更新 | `server.py:1115`、docs |

**风险与决策点**：
- 自签证书需 PDA 侧内置 CA 才免手动信任；若客户有多台 PDA，需保证 CA 一致且可轮换。
- 浏览器从"链接直带令牌"改 Cookie 会话，会改变现有"复制链接即可下载"的用法，需确认可接受。
- 若坚持零改造，可仅做 S1+S2（去 URL 令牌），保留明文 HTTP——但抓包仍可见箱数据与令牌。

**改造后验收标准**（本轮不执行，留作 S1~S5 落地后的回归项）：
1. 抓包（同网段任意工具）看不到明文 `X-Sync-Token` 与箱数据；
2. 浏览器首页 5 个入口不含 `token=` 仍可下载/打印；
3. PDA 配对 → 拉取 → 上传 → 对账 → 导出全链路在 HTTPS 下通过。

## 7. 执行顺序

1. **T4 自动化**（T4-01~04）：无副作用，先跑，确认代码基线。
2. **T3 迁移**（T3-01~03）：`connectedDebugAndroidTest`，独立测试库，不影响主库。
3. **T2 权限 + T3 备份恢复**（T2-02~04、T3-04~07）：需真机 UI 操作；**改动型用例（T3-05）最后做**，做完核对基线恢复。
4. **T4 真机链路**（T4-05~10）：建测试柜→门禁→正常→完成→撤销，闭环回基线；末了对账。
5. **T1 取证**（T1-01~05）：静态 + 抓首页 HTML，零改动。

> 安全边界：所有改动型用例必须可逆；任何一步失败先回滚到基线（撤销测试柜 / 恢复备份），再记录 FAIL，不带脏数据继续。
