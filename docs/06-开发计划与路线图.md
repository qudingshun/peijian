## 3. 后续开发计划（路线图）

优先级说明：**P0** 影响数据安全/正确性，应优先；**P1** 影响合规与可维护性；**P2** 为测试覆盖增强。所有剩余项都需要**真机或部署环境**，无法在纯代码层完成验证——下表"前置条件"列已标明。

### 3.1 P0 · 传输安全：令牌去 URL + HTTPS

| 项 | 内容 |
| --- | --- |
| 目标 | 配对令牌不再出现在 URL 查询参数与明文 HTTP 中，避免局域网抓包/浏览器历史泄露 |
| 现状 | PDA 已用 `X-Sync-Token` Header，服务端 `check_token` Header 与 query 两种都收；浏览器侧的导出、标签、`/reload` 链接仍带 `?token=`；`启动同步服务.bat` 以 `uvicorn --host 0.0.0.0 --port 8000` 明文启动 |
| 要做 | ① 服务端收敛为仅接受 Header（给浏览器链接配一个短期会话 Cookie 或本地回环白名单，保留可用的下载入口）；② 生成/内置自签证书或 Let's Encrypt，启动脚本改为 HTTPS；③ PDA 配对与 `serverUrl` 改存 `https://`，允许自签证书需用户确认或内置 CA；④ 更新 docs/03、docs/04 |
| 涉及 | `pc-server/server.py`、`启动同步服务.bat`、`SyncClient.kt`、`SettingsScreen`/配对逻辑、docs/03、docs/04 |
| 前置条件 | 一台可作为服务端的机器与证书；自签证书需 PDA 侧信任策略的明确决定 |
| 验收 | 抓包看不到明文令牌与箱数据；浏览器导出/标签在仅 Header 模式下仍可用；PDA 全链路（配对/拉取/上传/导出）在 HTTPS 下通过 |
